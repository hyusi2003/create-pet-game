# 自定义形象制作后接入产品与游戏

当用户同时要求自定义形象和游戏，或要求“做完形象直接放进产品”时使用。游戏默认读取用户已有的桌宠；不会因游戏开发额外生成一个角色。已授权制作并应用时完成导入、换上与验证，不停在图片/网页预览交付。仅授权收藏/导入时保留当前外观。

先读 [导入即时生效与避坑](live-import.md)：必须在目标运行客户端完成登记；独立进程离线写库不等于在线导入。

## 先按输出类型选择入口

| 产物 | 接入方式 |
| --- | --- |
| 游戏 HTML + 封面 | [游戏产品导入流程](product-import.md)，进入「传 vibe → 逗 TA 一下 → 游戏」。 |
| 透明 PNG 基础形象/动作帧 | 转成目标产品接受的 2D 外观包，再从「伙伴外观 → 导入形象」登记。 |
| 制作/预览 manifest、原始图集 | 先按目标动作与帧规范转换；文件名改后缀不能完成转换。 |
| 可编辑制作草稿 | 导入后继续编辑，不宣称是可换上的完整形象。 |
| 实时 3D 模型、布偶数据或 renderer/plugin 包 | 按真实 3D 外观与渲染契约接入；不能送进 2D 帧导入器。参考 [角色与风格](character-and-style.md)。 |

制作环境如有 `pet-doll-animation`，可用其流程完成保留宠物身份的 2D 布娃娃和动作；先读其 SKILL.md 及产品导入参考。该技能不是本包依赖，也未随包分发。没有它时仍按目标契约转换已提供的合法素材；新的图像生成遵从用户已确认的形象、模型与费用范围。

## 当前产品的本地 2D 导入契约

以下核对于 2026-10-14；目标产品更新或入口不同时先核对实际支持范围。当前支持数据型 `character.json + PNG` 或有效 `.petappearance`；不需要手工写入内置角色、plugins 或游戏资源目录。预览的 manifest/clip.json 不是产品描述符。

`character.json` 的文件名必须一致，素材路径相对其目录。最小待机示例对应 `idle/frame00.png`：

```json
{
  "name": "我的小猫",
  "anim": {
    "idle": {
      "dir": "idle", "base": "frame", "count": 1,
      "ext": "png", "start": 0, "pad": 2,
      "fps": 12, "loop": true, "face": 1, "idleBreathing": false
    }
  }
}
```

待机必需；对已有 walk/peek/drag/send 等动作逐项保留实际帧序、fps、loop、face。face 为 ±1，按实际绘制方向设置。当前入口只接受 PNG、标准动作、不含 variants/realtime/renderer/model。每动作 1–256 帧、fps 大于 0 且不超过 60；最多 256 张去重帧、2048 个帧位置，每帧不超过 2 MiB/1024 像素边长，原始帧总量不超过 96 MiB/160 MiPixels，描述符不超过 128 KiB。素材必须在包目录内，无软链接或目录穿越。缺失动作可触发产品回退，但不能把回退或最小静态包说成动作全部完成。

技能预览为左侧隐藏、产品标准素材为右侧隐藏时，对 peek 全序列镜像一次并保存到独立输出，不动原始付费图；unpeek 从转换后的序列倒序生成。已制作探头停留呼吸/眨眼时，完整保留 edgehide 的帧序、fps、loop 和固定边缘，不得压成 peek 末帧；只有未制作动态停留时才以最终露出的末帧静态保持。peek/unpeek 不循环；speak 可用基础静态图，base 不是运行时动作名。已经符合目标朝向的素材不再镜像。两侧入场/停留/缩回必须在真实桌宠复验。

追加/替换一个动作时，保留原包其余已验收动作的帧摘要、参数和原分辨率，不为迎合夹具放大图片。动态停留检查实际连续循环及窗口坐标固定；本地导入预算与网络素材预算分开，包能本地播放不等于可直接跨机传输，不能为了塞进网络预算静默删动作。

`.petappearance` 是带格式/版本的 gzip 数据包，不是普通 JSON 或 ZIP 改名；kind=draft 仅为编辑草稿。推荐用合法 `character.json` 导入成功后，从产品导出便携 `.petappearance`。有宿主检出时复用实际校验器，只有验证后的包才能声称兼容。

## 继续完成已授权的接入

1. 核对目标实例及任务范围，从看板「更多 → 伙伴外观 → 导入形象」选择包，确认成功反馈、库内名称/缩略图和动作预览。仅改源码目录或输出一份素材不算导入。
2. 用户要求应用时点击“使用形象”（旧版为“用这个形象”）换上，确认真实桌宠即时加载新帧。当前本地 2D 外观换上无需重启，保留原伙伴身份、名字、人设与记忆；仅收藏则不换上。不可为验证启动共享日常资料的第二实例，也不自动重启日常客户端。
3. 真实播放待机和已交付动作，检查透明边缘、大小、左右方向、探头/缩回连续性与缺失动作回退。导出便携包，在隔离新实例导入核对帧哈希、参数，并验证选择持久化；自动测试窗口首次绘制前隐藏。
4. 从真实产品入口打开游戏大厅，核对 SDK 的实际外观读取能力与模式，确认读的是刚换上的角色。2D 外观不会自动获得 3D 骨架，游戏的 3D 场景与角色适配另行实现。双方使用各自外观时分别验证两端。
5. 已打开作品的外观刷新取决于其读取/订阅机制；本次新做/改造的 Web 必须按 [完整动作与订阅](host-animations.md) 跟随换装，保留位置、进度和对局，无需重启宿主或重新开局。旧作品若未实现订阅则单列兼容限制，不把技能更新当作自动迁移。形象验收与游戏规则/联机验收分别报告。

当前环境缺少兼容产品时，仍完成可导入材料与说明，报告“形象材料完成，产品导入/换上/游戏读取待验”。交付记录包括包与帧摘要、目标实例/契约、导入 id、是否应用、缺失动作和实际验证证据。原始图、付费结果与已验收动作保留，不为格式转换重复生图。

外观与 SDK/存储的通用测试属于宿主，作品角色适配与玩法测试留在游戏项目；有独立形象处理器时，其素材转换测试留制作项目。公开 skill/PR 只提交说明和匿名夹具，不上传用户照片、生成形象或本机资料。导入本机不意味着插件市场登记、对外发送、公开发布或宿主发版。
